## 概述与范围

构建基于 Rust Stable、Pingora、OpenSSL 与 KDL 的轻量 Web 服务器，面向 Linux，优先 Debian。以单二进制提供 HTTP/HTTPS 反向代理、安全静态文件、多域名、静态证书与事务性 Reload，不复刻 Nginx/Caddy 全部生态。

P0 包含原文全部必需服务、配置、安全、可观测性和交付要求。P1 同样拆成必需完成本计划的详细任务，但不阻塞 008 的独立 P0 交付：包含 Snippet、可选自动 Reload、静态增强、Access Log、Prometheus 与可选 OpenTelemetry。可选表示运行时可关闭，不表示可以跳过本计划的实施验收。

非目标沿用原文：ACME、GUI、WAF、HTTP/3、Lua/WASM 插件、复杂负载均衡、服务发现、Ingress Controller、网关认证、分布式配置、每请求外部 API 选路、全面 Nginx 配置兼容和完整 CDN。不得将其混入现有任务。

```text
├── runtime/         # 完整快照、准备、发布与生命周期

deploy/
├── systemd/
└── podman/
scripts/bench/
docs/
├── architecture.md
└── plans/rill-web-server/
```

| 模块 | 职责与状态所有权 |
| --- | --- |
| config | 产生独立于 Pingora 的标准化配置与来源诊断，不发布状态 |
| routing | 构建不可变匹配表，不读取配置文件或证书 |
| runtime | 拥有活动快照和代次，唯一提交发布入口，协调旧快照回收 |
| proxy/static_files | 消费请求所固定的快照，不自行重载配置 |
| tls | 准备证书资源、按确认的代次读取方式处理握手；不得独立发布第二份活动配置 |
| control/cli | 权限、通信和结果展示；业务验证委托 runtime/config |
| observability | 受控事件与导出器，不改变代理结果 |

### 关键接口与数据流

接口与代次契约已在 docs/architecture.md 固化；002–004 已实现共享构建管线及初始 HTTP/TLS 快照，005 已提供 root 准备，007 已实现发布接口：

1. `load(path) → LoadedConfig → parse → ParsedConfig`：导入、解析、保留来源文件和位置。
2. `normalize → NormalizedConfig → validate → ValidatedConfig`：展开复用、消除简写、检查全局冲突。
3. `prepare → PreparedSnapshot`：构建路由、上游策略、root 资源和 TLS 上下文；任一失败无发布副作用。
4. 启动、check、reload 复用上述管线。check 不启动监听和管理服务；各实现阶段必须明确校验覆盖，004/005 后才具备完整资源校验。
5. `publish(PreparedSnapshot) → generation`：在重启项不变时通过一个 ArcSwap 根发布；禁止先换路由再换证书。
6. 新请求与新握手在明确时点固定快照；既有请求/连接继续持有所需资源。每个新请求或 HTTP/2 新流读取当前快照；旧连接保留握手证书，Host 必须与握手 SNI 一致，具体边界见架构文档第 4 节。
7. `reload request → prepare → publish/result`：受限 Unix Socket 返回关联标识、实际结果和诊断；CLI 等待结果，失败返回非零，超时明确表示结果未知。

监听地址等底层配置属于启动配置，不伪装成可热更新字段。配置和证书不在每请求热路径读取；不得以全局互斥锁串行化代理热路径。
