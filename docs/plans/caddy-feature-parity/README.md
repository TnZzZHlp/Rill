## 概述与事实边界

以 Rill 现有 Rust/Pingora/OpenSSL/KDL 架构为基础，补齐请求处理、鉴权、HTTP/2 上游、动态代理、正文变换、WebDAV 和日志能力。目标是可验证的行为覆盖，不是 Caddy 语法或生态全兼容。

差距文档包含调查与举例，不能全部作为已运行事实：25 个域名来自磁盘配置调查，不等于已验证全部在线；“约 12 个可迁移”没有逐站验收依据；606 MiB 为目录大小而非响应体大小；此前只抽查部分目录，没有证明所有 root 均无 sidecar；指标身份应以当前源码为准，历史文档中的十六进制长度描述存在误差。001 应原地核对并记录准确基线，不能用这些估计证明完成。

原文第 4 节的最小集合和“不建议实现”只是历史建议，本轮已批准范围覆盖其此前不建议的鉴权、WebDAV、h2/gRPC 和正文变换。新计划只扩展这些明确批准项，不重新打开原计划的其他非目标。

## 架构与目录

以下新增目录均为拟议，具体文件由 001 契约决定：

```text
src/
  config/          解析、来源、编译、限额与资源声明（现有）
  routing/         旧路由及新条件选择（现有）
  http_policy/     新增：规则链、头/路径、响应合成与错误处理
  auth/            新增：凭据准备、Basic/令牌验证
  body_transform/  新增：解码、跨块替换、在线编码
  webdav/          新增：存储、方法、属性、写事务与锁
  proxy/           现有：上游协议、gRPC 与动态目标隔离
  static_files/    现有：只读表示及受约束 root 打开
  observability/   现有：日志策略、身份、输出与轮转
  runtime/         现有：候选、资源激活、单根发布及共享状态
```

main/CLI 不承载业务规则。统一构建管线产生不可变政策，编译正则/条件、验证凭据、准备受约束 root、声明日志资源；check 不创建文件、修改 DAV 状态或联系后端。所有潜在写资源须以无副作用准备和提交激活协议处理，不允许“check 成功”掩盖无法验证的资源。日志目标预备、回滚与可写检查的精确边界由 001 定稿。

请求读取单个快照 → 旧路由或新链 → 匹配/鉴权/请求变换 → 动作 → 有限错误处理 → 响应条件/受限解码/替换/编码/最终头一致化 → 输出及日志。具体过滤顺序在 001 固定；请求变换不能覆盖安全身份、framing 或绕过 root 校验。

独立于快照的进程状态只用于确有跨请求生命周期的锁、日志 worker、池与限额，由 runtime 统一持有并以稳定身份关联；政策仍在单快照原子发布。旧请求可完成旧政策，资源在最后持有者释放后回收。移除/更换 DAV root 与锁状态的行为不能由短命快照自然析构决定。
