## 目标与范围

冻结 2.1–2.9 及 2.10 日志身份的契约；仅进行隔离技术验证，不实现生产功能。

排除 OTLP/追踪及新增 metrics 能力、差距文档 2.11、生产切换，以及分配给其他阶段的实现。现有观测代码删除属于用户后续独立工作，不在本阶段执行。

## 设计

### 模块边界与目标路径

src/config/、src/routing/、src/proxy/、src/static_files/、src/runtime/、src/observability/（只读调查）；tests/feasibility/（经实施授权后的最小验证）。

业务逻辑放在所属模块，main/CLI 仅编排。共享配置、动作和资源类型经统一管线准备；请求固定一个快照，各过滤器不得重新读取活动配置。

### 接口与运行行为

形成规则链编译模型、动作/过滤器接口、响应错误分类、WebDAV 稳定存储身份与锁所有权、日志候选资源生命周期。对上游 h2 和 trailers 接口逐项调查，不能因 Pingora 无接口而静默换框架。无界正则算法必须证明输出与输入分块无关；任意固定重叠窗口不能作为正确性依据。

外部输入可恢复、脱敏、严格拒绝未知字段；资源超限按冻结契约失败。新增文件/状态不得在失败候选中污染活动资源。所有测试和验证在隔离环境进行，不操作生产 Caddy。

## 实施交接契约

1. 生成计划不启动实施。任务完成且所需检查通过后勾选任务；验收实际通过后勾选验收，并记录命令或步骤、结果和证据位置。总目标只能在完整结果验证后勾选，不凭推测批量更新。
2. 全部必需任务、验收及交付物满足才可完成子计划；失败、跳过、阻塞、未执行的检查保持未勾选并阻止完成。范围变更必须获批。
3. 提交前同步子计划和总计划状态，审阅 Git 工作区及暂存区；只暂存本阶段明确路径或已审阅代码块，保留无关用户变更、预先暂存内容和其他阶段工作。无法安全分离则暂停询问。
4. 每个完成的子计划单独创建一次完成提交，成功后才可开始依赖阶段；不合并多个阶段、不逐任务创建完成提交。采用 `feat(caddy-feature-parity): complete subplan NNN - phase-name`。
5. 验证提交成功并报告哈希；失败时说明仍待提交。Git 不可用、非仓库、身份缺失、钩子失败或变更已提交时停止询问；不得自动初始化 Git、修改身份、绕过钩子、改写历史、推送或创建空提交。
6. 规划生成和仅更新计划不创建提交。实施需要单独授权；本计划不授权子代理或线上部署。
