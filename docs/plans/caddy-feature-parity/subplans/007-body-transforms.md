## 目标与范围

字面量及 Rust 正则跨块替换、捕获替换与顺序规则；gzip/zstd 在线压缩及已有 sidecar 协调。

排除 OTLP/追踪及新增 metrics 能力、差距文档 2.11、生产切换，以及分配给其他阶段的实现。现有观测代码删除属于用户后续独立工作，不在本阶段执行。

依赖阶段已验收并独立提交；已获得本阶段实施授权；工作区可安全分离。除 001 外，001 的契约与可行性必须已获用户明确验收。原计划的完成记录不替代本阶段验证。

## 设计

### 模块边界与目标路径

拟新增 src/body_transform/、src/proxy/、src/static_files/、src/http_policy/、src/config/、tests/body_transform.rs 与 tests/body_transform/。

业务逻辑放在所属模块，main/CLI 仅编排。共享配置、动作和资源类型经统一管线准备；请求固定一个快照，各过滤器不得重新读取活动配置。

### 接口与运行行为

采用 001 验证的流式匹配算法，保留尚不能确定的输入并设置单请求/全局上限；无界正则允许延迟直至 EOF，不承诺提前输出，不能主动完整聚合正文。超限在发送前返回契约错误，发送后中止并记录失败。按 MIME 显式选择，不处理 gRPC/SSE/WS。处理压缩源时先受限解码再替换再按协商编码，限制解压输出和膨胀；不靠任意窗口截断匹配。

外部输入可恢复、脱敏、严格拒绝未知字段；资源超限按冻结契约失败。新增文件/状态不得在失败候选中污染活动资源。所有测试和验证在隔离环境进行，不操作生产 Caddy。
